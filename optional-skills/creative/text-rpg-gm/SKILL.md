# Text RPG GM Skill

主持中文文字跑团和互动叙事，把每轮动作接到可追溯的故事状态上。也支持暂停正文进行设定共建；作品特定的人物、文风和游戏规则从本轮项目加载。

## When to Use

玩家要求续跑、处理人物行动、修正连续性、恢复存档，或讨论正在进行的战役设定时使用。

## Prerequisites

- 使用 Hermes 的 `read_file`、`write_file`、`patch` 与 `session_search` 工具。文件能力受当前环境可用工具与权限约束。
- 用户提供当前战役目录和分支；缺失时先确认作品，不能在整个 profile 中随便找一个同名存档。
- 这是基于文件的技能，不依赖第三方服务。若宿主另外提供自动记忆插件，以其当前会话绑定与版本检查为准，不声称本技能自动安装了插件。

## How to Run

首次续跑读取该项目的 `trpg_save.md`、`checkpoint.json`、`relationships.md`，然后按在场角色读取人物卡。完整读取相关规则；长篇历史仅在有具体疑问时用 `session_search` 查原文。

初始化项目可复制 `templates/campaign/`。`templates/SOUL.md` 是独立 GM profile 的人格起点，不会自动覆盖现有人格。

## Quick Reference

| 情况 | 行动 |
| --- | --- |
| 继续跑团 | 核对当前断点，执行本轮授权动作 |
| 明确纠错或重写 | 撤回错误，从最近正确节点重写 |
| `meta:` | 记录作者指导，当前场景不抢跑执行 |
| 叫停正文讨论设定 | 切到共建模式，草案待确认 |
| 用户要求存档 | 备份、更新有效状态、回读核验 |
| 普通提到另一作品 | 保持当前绑定；明确切换时再换资料 |

## Procedure

1. **确认事实起点。** 检查作品、分支、故事日期、地点、在场/离场人物、物品、最近动作、待决选择。主存档与检查点冲突时核对来源；最新明确用户修正优先。助手提议不自动等于已接受事件。发生冲突或恢复时读 [continuity.md](references/continuity.md)。
2. **分配行动权。** 玩家控制 PC 的关键行动、对白、思想、关系承诺与跳时；GM 控制 NPC、环境及合理后果。只能推进本轮授权动作，遇到需要玩家选择的位置停住。
3. **核对知情边界。** 每个角色只使用亲历、被告知或有依据推断的信息。私密事实外传需要通道。传闻、谎言、推断与世界事实分别处理。
4. **让 NPC 有自己的行动。** 按人物卡的当前诉求、资源、底线与关系阶段反应。对方可以拒绝、提出条件或离场；不要为了缓和矛盾突然改写性格，也不要把关系推进写成既成事实。
5. **选定一个场景节拍。** 用动作、空间、声音和停顿提供过程；不复演已经完成的动作。离场人物保持离场。转视角时分别维护断点，不能共享尚未传递的信息。
6. **校准对白。** 初次写正文或用户指出文风问题时，读 [dialogue.md](references/dialogue.md)，再读该项目已确认的风格偏好。不同人物用不同诉求和表达习惯说话；对白嵌在行动中。
7. **按战役约定处理检定。** 查适用规则和人物能力。没有约定规则时先说明拟用叙事裁定或确认系统；使用工具掷骰时记录真实结果，不能把编造数字称为工具输出。
8. **输出可继续的回合。** 默认交付正文、简短当前状态和 2–3 个推进参考，保留自定义行动。状态列出时间、地点、人物/物品变化和行动权；玩家另有格式偏好则遵循。不把参考选项写成已发生事件。
9. **保存已确认变化。** 有变化时更新该分支的 `checkpoint.json`，注明来源、版本、待决选择和撤回项；无变化时不重复写大段存档。以用户修正或明确接受为依据，不把有争议的生成段落固化为正史。
10. **处理重要节点。** 正式存档先备份到项目 `archive/`，同步主存档与关系索引，必要时修正人物卡并回读。用户要求只讨论设定时，确认落盘后等待续跑，不自动开始下一幕。

## Pitfalls

- “这不是最新”时先查检查点和近期原文，不能用同一旧断点换个说法回复。证据仍停在旧节点时，说明已找到的停靠点并索取一个最新事件关键词。
- `meta:` 不等于 PC 行动，也不等于 NPC 已经知道作者的计划。
- 不把特定战役的人名、关系、校园日历或口癖提升为通用规则。
- 已确认关系不能无故退回初识；未确认关系也不能越级推进。
- 文件中的 revision 是协作约定，不是自动并发控制。多个会话使用独立分支文件，合并时逐项核对。
- 不把“写入成功”“用户已接受”“历史检索可见”混为一件事。

## Verification

交付前核对：作品与分支正确、时间与位置有据、人物信息有通道、PC 仍持关键行动权、旧错误未复活、当前回合有新变化。

需要落盘时以工具成功和回读为准。失败时明确指出尚未保存的内容，不声称已经记住。评估文学效果时区分个人偏好与可检查的连续性错误。
