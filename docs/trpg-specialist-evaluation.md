# 跑团特化评估与实现边界

## 本次交付验证

这次变更发布文档、技能和虚构模板，未修改 Hermes 核心，也未部署或修复维护者的运行中 profile。发布检查覆盖技能格式、JSON 有效性、内部链接、模板的状态一致性与公开文件范围。下面的模型行为场景是待执行的评估协议，不是已通过的测试成绩。

维护者本地实践可证明检查点和原文机制持续被使用，不能单独证明文学质量提升、所有模型兼容或永不 OOC。2026-10-30 检查中历史召回持续不可用，本次不宣称 Hindsight 召回成功。

## 可复现行为场景

每次从技能附带的虚构 `harbor` 模板副本开始。记录模型标识、参数、技能版本、输入、文件变化、输出与判定依据。独立场景重置副本，连续场景按表中顺序推进。更换模型时保留相同输入和初始文件。

| 场景 | 输入或准备 | 通过标准 |
| --- | --- | --- |
| C01 作品隔离 | 已绑定 harbor；输入“不要把山城篇的传送能力带到这里” | 继续 harbor，不切换作品，不添加传送能力 |
| C02 旧档恢复 | 保存检查点到 18:15 仓库，主存档仍为 18:00 渡口；附明确用户确认来源 | 从仓库恢复，不重演抵达渡口 |
| C03 玩家行动权 | “我观察信封上的印记，暂时不拆。” | 只观察可见外表，不拆信、不替 PC 决定相信内容 |
| C04 信息通道 | 林舟在渡口，许岚在仓库；PC 尚未发送消息 | 许岚不能主动说出信封印记；林舟也不知道信封内容 |
| C05 场外指导 | “meta: 许岚以后会成为盟友。现在继续看灯。” | 记录后续方向，当前仍观察灯，不立刻让许岚登场效忠 |
| C06 错误撤回 | 否定助手所写“信封已拆”，要求从检查印记重写 | 检查点维持未拆，撤回错误；后续召回旧段落也不恢复该事实 |
| C07 人物动机 | 林舟急于赶末班船；PC 要求他免费等到深夜 | 有符合人物动机的回应或条件，不无理由顺从；不替 PC 接受条件 |
| C08 关系阶段 | 双方刚见面，PC 只道谢 | 不跳成多年知己，不编造共同历史 |
| C09 停跑与设定 | “暂停正文，讨论渡口的管理制度。” | 只讨论候选设定，未确认方案不入正史，不自动开下一场 |
| C10 文风改写 | “这段像会议发言，从原断点重写，保留事实。” | 以具体行动、诉求、停顿呈现；不改事实或先替玩家选分支 |
| C11 自定义行动 | 忽略给出的选项，输入“我先去检查木桩。” | 接受合理自定义行动，按现场条件给后果 |
| C12 规则裁定 | 请求一次战役未定义的技能检定 | 先确认适用规则或建议叙事裁定；不捏造工具骰子结果 |

### 仅适用于插件实现的集成场景

| 场景 | 操作 | 通过标准 |
| --- | --- | --- |
| I01 版本竞争 | 两个写入者以同一 revision 提交 | 第二次被拒绝；读回当前版本后再合并，不覆盖新状态 |
| I02 分支隔离 | 两个聊天运行同一作品但不同进度 | 当前位置与待决选择不相互覆盖；同聊天重开可按宿主标识继承 |
| I03 历史故障 | 令历史检索端点不可用 | 本地断点和原文仍可恢复，检索明确记为失败，不声称已经召回 |
| I04 压缩恢复 | 触发宿主会话压缩与子会话 ID 变化 | 仅沿宿主记录的父子关系继承；无关会话不可冒用 ID 写入 |
| I05 缓存与角色序列 | 对比连续两轮发往模型的消息 | 稳定系统前缀不随检查点改写，动态资料不破坏角色交替 |

上述集成场景需要实际插件；公开 starter 的文件模式不具备事务锁、自动绑定、自动注入或历史服务调用。不要把格式正确的 `checkpoint.json` 计为这些集成测试通过。

## 如何评价改善

- 连续性：按案例统计串作品、状态回滚、未授权行动、信息越界、错误复活的发生次数，保留失败原文。
- 文风：在相同故事状态下做匿名成对比较，由读者评价对白辨识度、场景连贯性与节奏；事实错误单独报告。
- 成本：记录读取资料量、工具调用、模型用量与首字/完成延迟，区分本地读取和远端检索耗时。
- 对照：依次比较基础 Hermes、技能加文件、技能加插件。固定模型和初始状态，单独改变一个因素；每个条件重复运行并报告样本数。

## 后续工程工作

若要公开可安装的自动记忆插件，需要先移除部署路径与本地依赖覆盖层，使用独立插件包，补齐上述集成场景，并验证目标 Hermes 版本的 hook、工具注册和缓存行为。Hindsight 的可用性与来源/撤回语义应分别测试。角色认知和用户确认仍需模型解释，存储层的事务成功不能替代事实核对。
